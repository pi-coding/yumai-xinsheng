# 小程序校验脚本

小程序工程没有构建步骤，也没有单元测试框架，质量靠这三个 Node 脚本兜住。
它们不参与小程序打包（`project.config.json` 的 `packOptions.ignore` 已排除本目录）。

```bash
# 在项目根目录执行，或在本目录执行都行（脚本自己按文件位置向上找工程）
node miniprogram/_tools/verify_mp.js    # 静态校验 + 数据/引擎保真度
node miniprogram/_tools/smoke_mp.js     # mock wx 运行时冒烟
```

## verify_mp.js — 静态校验 + 保真度

| 检查 | 说明 |
|---|---|
| JS 语法 | 20 个 `.js` 全部用 `vm.Script` 编译一遍 |
| JSON 合法性 | 12 个 `.json` 全部 `JSON.parse` |
| 页面注册 | `app.json` 里 9 个页面、tabBar 5 项，对应文件都存在 |
| WXML 引用 | 绑定的处理函数在 JS 里已定义；表达式里的根标识符在 `data` 里已声明 |
| 数据保真度 | `utils/data.js` 与参考实现（H5 版）逐字段一致 |
| 引擎保真度 | 8 段文本 × 2 方向 × 5 语境 × 6 语气 × 4 语法形式 = **1920 组**输出与出处注释一致 |

### 保真度对照源有两条路

「附录五-技术复原」是调研报告附录五的离线存档，**不随本仓库分发**。所以：

- **本机有存档** → 直接读 `附录五-技术复原/小程序复现/语脉新生.html`，
  把里面的 `localAdapt` 抽出来当参照，逐组比 `output` 与 `notes`（最强，能指出第一处差异）。
- **没有存档**（从 GitHub 克隆的默认情况）→ 比对 `adapt-baseline.json` 里固化的指纹：
  每个组合存一个 FNV-1a 32 位哈希，共 1920 个，另存 5 项数据指纹。
  等价于「输出没变过」的回归保护，但报不出具体是哪段文本变了 —— 只会给出第一个不一致的组合与哈希。

`adapt-baseline.json` 由 `gen-baseline.js` 生成：

```bash
node miniprogram/_tools/gen-baseline.js   # 需要本机存在附录五存档
```

它会在生成前先校验「当前小程序引擎与 H5 原文逐条一致」，不一致就拒绝生成 ——
避免把已经漂移的结果固化成基线。

> **改动 `utils/engine.js` 或 `utils/data.js` 后**：如果本机没有附录五存档，
> 基线就会报错。这是预期行为（说明你正在改变对外承诺的输出）。
> 确认改动是正确的，再找一台有存档的机器重新生成基线。

## smoke_mp.js — 运行时冒烟

mock 掉 `wx` / `Page` / `getApp`，按真实生命周期把页面走一遍，共 **14 步**：

离线兜底 9 项（首页、书库、详情、收藏、工坊、日历、核验、设置）→ 登录合并书架 →
服务端通道三条（书库 / 核验 / 日历取服务端数据并标注来源）→ 失败兜底链 → 只读区折叠与「我的」页。

能抓到「语法没问题但一跑就白屏」这类错误，抓不到真实渲染效果。
