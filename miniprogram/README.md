# 语脉新生 · 微信小程序工程

调研报告「附录五 · 团队设计的科普工具」中 **T1「古风转译小程序·语脉新生」** 的微信原生小程序实现。

原应用是**飞书应用引擎 H5**（报告仅存访问链接与 4 张界面图，无源码）。本工程按界面图与正文描述重建，
五个模块与数据字段与重建的 H5 单文件版一致，改编引擎为**同一套逻辑的逐条对齐移植**
（H5 版属报告附录的离线存档，不随本仓库分发；`_tools/adapt-baseline.json` 固化了它 1920 组输出的指纹，
用来守住这条约束）。

**本端是「全栈版」小程序**：优先进 `server` 的 REST 接口，后端不可用时自动回退内置数据，
界面上明确标注当前来源（服务端 / 离线），不会把离线数据当作服务端结果显示。

## 一、运行方式

1. 打开**微信开发者工具** → 「导入项目」。
2. 目录选到本文件夹（顶层 `miniprogram/`，**不要再往上选一级**）。
3. **AppID 一定不能留 `touristappid`**。2025 年以后的开发者工具已禁用游客 AppID，导入时会红字提示
   「游客 AppID 无法使用此功能」→ 点 AppID 右侧的蓝色「**测试号**」链接，按提示微信扫码后工具会自动填入
   一个可用 AppID（首次会先要求登录）。`project.config.json` 里的 `touristappid` 只是占位，
   导入成功后开发者工具会把它改写成本机实际使用的 AppID，属正常现象。
   没有微信账号可扫时无法使用游客身份，只能先注册小程序账号拿正式 AppID。
4. 编译后即可运行。**无 npm 依赖、无需构建。**

导入成功后开发者工具会做两件事，都属正常：

- 把 `project.config.json` 的 `appid` 改成实际使用的 AppID；
- 生成 `project.private.config.json`（本机私有设置：基础库版本、热重载开关等）。
  这个文件只跟你这台机器有关，**不要当成工程源码改动**。

后端可选，两种跑法都行：

| 场景 | 做法 | 表现 |
|---|---|---|
| 连后端（推荐） | 先跑 `server/start.bat`，小程序「我的 → 登录」用 `demo / demo123` | 书库/日历/核验/改编/收藏走后端，可跨设备同步 |
| 纯离线 | 什么都不起，直接编译 | 自动回退内置数据，页面标「离线」，功能不残缺 |

后端地址默认 `http://localhost:8081`，在**登录页**或**设置 → 服务端**里可改
（真机预览要改成电脑局域网 IP，并在微信公众平台登记 request 合法域名；开发者工具已关 `urlCheck`）。

> 真机预览：点开发者工具右上角「预览」，用微信扫码。

## 四、数据与引擎

| 项 | 数量 |
|---|---|
| 古籍元数据 | **60 部**（经部 15／史部 14／子部 16／集部 15） |
| 语料对 | **118 条**（98 条来自 T2 语料库并带真实出典，20 条补充条目） |
| 文言词典 | **434 条**（白话→文言 203／文言→白话 231） |
| 日历词条 | **16 条** |
| 误传案例（核验库） | **43 条**（伪古风 24／出处讹变 12／出处存疑 7） |
| 真典条目（核验库） | **47 条** |
| 名句摘录 | **46 部书共 77 条**，句后标注篇名；余 14 部为韵书/政书/类书一类，只给要旨不摘句 |

改编引擎（`utils/engine.js`）沿用原实现的四输入 → 一输出结构：

```
语境 · 语气 · 语法形式 · 原文  →  规范古风用语
```

1. **语料对命中 → 掩码保护**：118 条语料对正则最长匹配，命中后先掩码，避免后续词典把已正确的古籍原句改坏；
2. **词典单次扫描替换**：按词长降序，替换结果不再被二次扫描，避免「不可 → 不行 → 不走」连锁改写；
3. **语法形式变换**：原词使用／诗词语素拼接／网络改编／文言句式；
4. **语境·语气修饰**：语境前缀 + 语气首尾词；
5. 还原被保护的古籍原句，并输出**所用规则与出处**。

**可选接入大模型**：设置页可切换「本地规则引擎／大模型 API」，填 OpenAI 兼容端点、Key、模型名，
并提供**连通性测试**；调用失败自动回退本地引擎。

> ⚠️ 小程序客户端直连第三方 API 需要在微信公众平台「开发管理 → 服务器域名 → request 合法域名」
> 中登记该地址，否则请求会被拦截。不便登记时建议改用云函数中转，或直接用本地引擎（默认）。

### 数据从哪来：一档标注 + 三级兜底

所有取数都过 `utils/repo.js` 的 `tryServer(fn, fallback)`，统一返回 `{data, source}`：

| source | 含义 | 界面表现 |
|---|---|---|
| `server` | 来自 `server` | 页头显示「服务端」 |
| `local` | 后端不可达，已回退内置数据 | 页头显示「离线」，首屏 `conn` 行给出原因 |

规则细节：

- **`code === 401` 不兜底**——没登录就是没登录，直接引导去登录页，而不是拿本地数据糊过去；
- 401 时先自动 `POST /api/auth/refresh` 试一次，失败才跳登录；
- 断网后有 **20 s 冷却**，期间不再逐页等 6 s 超时；`/api/health` 探测超时 2.5 s；
- **改编是三级链**：后端 `/api/adapt` → 用户自带大模型 → 本地规则引擎，任一级成功即停，界面标出实际用的是哪一级；
- 登录成功后调 `POST /api/book-favorites/merge`，把本地 `ymxs_favBooks` 并入服务端书架（**只增不删**）。

## 五、与原 H5 复现版的差异（如实说明）

| 项 | 原 H5 版 | 本小程序版 |
|---|---|---|
| 存储 | `localStorage` | `wx.getStorageSync / setStorageSync`（键名沿用 `ymxs_` 前缀） |
| 古籍封面 | 程序生成 SVG（data URI） | **CSS 渐变 + 衬线字**（小程序 `image` 对 SVG 支持不保证，故改为纯样式实现，配色与生成算法一致：同名同色） |
| 导航 | 左侧栏 + 顶栏面包屑 | tabBar（5 项）+ 原生导航栏 |
| 弹层 | 模态框 | 收藏等操作改为**就地切换**，古籍详情独立成页 |
| 快捷键 | `Ctrl/⌘ + Enter` 直接改编、`←/→` 翻词条 | 小程序不支持键盘快捷键（触屏交互替代） |
| 大模型调用 | `fetch` | `wx.request`（受合法域名限制）+ 连通性测试 |

## 六、界面规范（简洁 + 指引性）

改版目标：首屏只回答「现在该做什么」，每页都给出「下一步去哪」。公共组件统一写在 `app.wxss`，
页面只做组合，不各写一套。

| 组件 | 类名 | 用途 |
|---|---|---|
| 页头 | `.pagehd` + `.pt` / `.pd` / `.pa` | 标题 + 一句话说明 + 右侧当前态（数量或入口） |
| **来源徽章** | `.srcb` + `.on` / `.off` / `.wait` | 页头右侧一句话说清「这批数据哪来的」：服务端 / 离线 / 检测中 |
| **离线提示条** | `.offbar` + `.ot` / `.oa` | 只在需要后端的页面出现：一句话说清后果 + 一个修复动作（如「用本机地址」） |
| 步骤路径 | `.steps` + `.step` | 首页「三步上手」，整行可点，替代大段导语 |
| 下一步条 | `.nextbar` | 页尾把人往下一环推，**除首页与设置外每页都有一条** |
| 空态 | `.empty` + `.em` / `.et` / `.ed` / `.ea` | 标题 + 说明 + 一个主行动按钮（如「清空筛选」「看全部案例」） |
| 折叠摘要 | `.fold` + `.ft` / `.fv` / `.far` | 参数区默认收起，只露当前值，点开再展开 |
| **折叠块** | `.acc` + `.acc-h` / `.acc-b` | 只读参考信息默认收起，标题行右侧显示摘要（如「118 条 · 只读」） |
| 一行数据 | `.databar` | 六行统计压成一行，降低首屏高度 |

配套交互改动：

1. **首页化简**：hero 只留标题 + 一句 + 两个主按钮；新增「三步上手」（挑句 → 核验 → 改写存集）；
   入口从 6 个收敛到 3 个（书库 / 日历 / 收藏）；六行内嵌数据压成一行。
2. **工坊**：输入在最前，参数区（语境 · 语气 · 语法形式）默认收起，只显示当前值；
   结果区加「核验这句」。
3. **核验**：示例按钮提到输入框上方（不知道怎么用的人可直接看结果）；结果末尾「查完想改写成规范说法？」
   一键带原文进工坊。
4. **双向带参**：工坊 → 核验走 `navigateTo ?text=`（`verify.onLoad` 读到即自动核验）；
   核验 → 工坊走 `switchTab` + `store.set('prefill')`。
5. **空态可自救**：书库无结果给「清空筛选」（同时复位部类与关键词）；案例库无结果给「看全部案例」。

### 第二轮（全栈化之后再收一遍）

全栈化给页面加了不少「状态说明」，容易把首屏再次撑长，因此专门做了一轮减法：

| 页面 | 改动 | 效果 |
|---|---|---|
| 首页 | 删掉底部「内嵌数据」整段（设置页已有，重复）；「我的数据」三格并进一张可点卡片，箭头直指收藏页 | 少一整块，首屏只留「该做什么」 |
| 登录 | 离线提示条**提到表单上方**（先告诉能不能连上，再让人输密码）；后端地址折叠；末尾加「不登录也能用 → 先去书库逛逛」 | 登录不再是一条死路 |
| 收藏 | 页头两行长句压成一行 + 来源徽章；tab 去 emoji；「服务端改编记录」改成默认收起的折叠块 | 与本机作品集不再混淆，默认高度减半 |
| 设置 | 服务端说明压到一行；「内嵌数据」「关于」各自折叠（摘要直接给数字）；保存按钮移到引擎区末尾并改名「保存引擎设置」 | 首屏只留能改的项 |
| 书库 / 详情 / 日历 | 各补一条 `.nextbar`（去核验 / 去改编工坊） | 每个列表页都有下一步，不再走到底就断 |

## 八、已知局限

- **未做视觉实机验收**：本机无浏览器／真机自动化环境，上述验收只覆盖「接口契约 + 逻辑 + JS 语法与数据引用」，
  **页面渲染效果需要你在微信开发者工具里打开确认**（覆盖层叠、长文本折行、卡片两列宽度等）。
- 原应用的**插画与字体无法获取**，封面为程序化生成，风格贴近但非原图。
- 古籍元数据为公开文献学常识整理，非古籍原文抄录；存疑者（如《列子》《管子》的成书与作者）按「旧题」如实标注。
- 名句摘录取自各书**通行本**并标注篇名，供核对用，**不代替原文校勘**；韵书、政书、类书等工具型典籍不强行摘句。
- 溯源核验的判定范围是「误传 43 + 真典 47 + 语料对 118」这套索引，超出范围一律返回「未收录」，
  页面与结论里都写明**未收录 ≠ 伪古风**；可信度是派生指标，不是报告统计值。
- 日历词条中「无人与我立黄昏」被原始语料库标注为沈复《浮生六记》，实为网络误传，此处按**辟谣条目**处理。
- 本工程**未改动**上级目录中逐字节提取的原始语料库（`../../语料库程序/古风网语语料库-v9.0.html`）。
