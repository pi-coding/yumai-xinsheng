# 语脉新生 · 后端（Spring Boot + MySQL + Redis，同时托管 Web 前端）

把《语脉新生——古风网语赋能中华文脉》调研报告里「面向大众的古风科普工具」的设想，
落成一个可登录、可收藏、可统计的在线平台。

两条落地路径：

1. **服务端重写**——报告里的五大模块（工作台总览 / 古籍书库 / 语言改编工坊 / 我的收藏 / 科普日历）
   在本平台用 Spring Boot + MySQL + Redis 重新实现，并新增答题闯关、数据看板与**溯源核验**。
2. **原样托管（可选）**——如果本机存在报告附录的离线存档 `附录五-技术复原/`，
   它的 18 个单文件 HTML 工具与语料库原始数据会挂到 `/archive/**`，在「工具集」视图里按 6 组呈现
   （24 项索引，逐项显示磁盘存在性与体积），点开即运行，一个字节都没有改动。
   **该存档不随本仓库分发**，缺失时 `/api/archive/catalog` 返回 `available=false` 与提示，
   其余功能完全不受影响。

其中「溯源核验」是本次最重要的一次创新：报告的核心命题是**反伪古风**，而原设想里这一命题只有
一个只读的单文件工具。本版本把它的数据与判定口径搬到服务端，
让平台本身具备「判断一句古风文案到底有没有出处」的能力，而不是只把结论写成文字。

## 一、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 ES Module + CSS（零构建、零 CDN） | 由后端静态托管，断网可用 |
| 后端 | Spring Boot 2.7.18 / JDK 11 | 端口 **8081**（避开本机 8080 占用的系统进程） |
| 持久化 | MySQL 8.0 + Spring Data JPA | 库名 `yumai`，首次启动自动建库建表并播种 |
| 缓存 | Redis 6/7 + Lettuce | 令牌白名单、热榜、结果缓存、限流、UV/PV |
| 鉴权 | JWT（HS256）+ Redis 白名单 | 退出登录即时失效，支持刷新令牌 |
| 口令 | PBKDF2-HMAC-SHA256（12000 轮 + 随机盐） | 未引入 Spring Security，保持依赖精简 |

### 归档目录怎么找

jar 里**不带**这 13 MB 静态资产（避免产物翻倍、避免与源目录漂移），运行时按下列顺序探测：

1. `application.yml` 的 `yumai.archive.dir`（绝对路径或相对工作目录）；
2. 从工作目录起逐级向上 5 层，找名为 `附录五-技术复原` 且含 `项目总览.html` 的目录。

探测到即把 `/archive/**` 映射到该目录（`file:` 协议），因此归档里的单文件应用**不需要改动任何相对链接**。
探测不到时「工具集」视图会给出明确提示与两种修复方式，其余功能不受影响。

### 前端目录怎么找

同一套思路，前端 SPA 也已从 jar 里**移出**为并列的 `frontend/`（改样式、改页面不必重新打包）。探测顺序：

1. `application.yml` 的 `yumai.web.dir`（绝对路径或相对工作目录）；
2. 从工作目录起逐级向上 5 层，找名为 `frontend` 且含 `index.html` 的目录；
3. 都找不到 → 回落到 jar 内的 `static/`。

前两级命中时，`/**` 的静态资源位置是 `[外置前端目录, classpath:/static/]`：

- **外置目录优先**，因此 `index.html`、`js/`、`css/`、`assets/` 全部走真实文件，热改即生效；
- jar 内 `static/` 只保留一个**兜底自检页**（`static/index.html`），它会告诉你该把前端目录放在哪、
  该在 `application.yml` 里写什么，并给出 `/api/health` 的探测链接——不会白屏；
- `/archive/**`、`/api/**` 不受影响，与前端目录各走各的映射。

> 从 jar 所在目录启动（`start.ps1` 即如此）时，向上 5 层足以覆盖
> `server/backend/target/` → 后端根 → 项目根 这几级，一般无需手工配置。
> 若把 jar 拷到别处单独跑，请显式设置 `yumai.web.dir`。

后端 13 个模块：`auth` `corpus` `adapt` `favorites` `book-favorites` `quiz` `stats` `daily` `books` `calendar` `archive` `verify` `meta`。

> `favorites` 与 `book-favorites` 不是一回事：前者的收藏对象是**语料行**（`corpus_id`），后者是**书目名**（`book_name`，对应书库 60 部），专供小程序端「我的 · 古籍」页签使用，两者语义不同，因此分两张表（`t_favorite` / `t_book_fav`），不要混用。

**改编引擎**（`service/AdaptService.java`）算法与附录五 H5 版 `localAdapt` 逐条对齐：
语料对最长匹配 → 掩码保护 → 文言词表单次扫描（结果不再被扫，避免「不可→弗可」连锁改写）→
句法变换（将字句 / 为…所 / 之字结构）→ 还原掩码 → 语境前缀与语气尾缀。
相同输入的输出与 Web 版一致，测试用例见下方验收记录。
改编结果现在额外返回**改写依据链**（`traces`）：每一步改了哪些字、依据哪条语料对／词表／句法规则，
都能对回语料库回查——前端在结果下方逐步列出来，不是黑箱。

### 溯源核验：把报告的「反伪古风」做成平台能力

`service/VerdictBase.java` 把附录五 P1 的判定数据（误传案例 43 条、真典 47 条、语料对 118 条）
在启动时建成 555 条索引，`VerifyService` 用与 P1 **完全一致**的口径判定：

| 结论 | 触发条件 |
|---|---|
| 伪古风 | 命中误传库且等级为「伪古风」（查无此句、今人拟古之作） |
| 出处讹变 | 句子确有，但出处被张冠李戴 |
| 出处存疑 | 有相似古句，归属不确定 |
| 真伪混杂 | 同一段文案里既有可溯源真句，又有误传条目 |
| 有据可考 | 只命中真典库或语料对 |
| 未收录 | 一条都没命中（**明确声明：未收录 ≠ 伪古风**） |

- **逐句判定**：换行即分段（≤20 段），每段给出命中条目、常见误标、实际情况、修改建议、核验方式；
- **可信度**：`100 − 伪古风×35 − 出处讹变×22 − 出处存疑×12 − 现代网语×3`，无可溯源项时封顶 40，
  一条都没命中时不出分（显示「—」）。页面与接口文档都注明这是**平台派生指标，不是报告统计结果**；
- **误传案例库**：43 条按等级筛选、分页检索，每条都能「拿它试一次核验」；
- **跨库提示**：关键词在误传库无结果、却在真典库命中时（例如搜「纳兰」），
  界面会提示「这是真句」，避免把真句误判成伪古风；
- **Redis**：结果按 `sha256(text)[:24]` 缓存 1 小时，结论计数进 Hash；登录用户的核验流水写入 MySQL。

## 五、Redis 用法（不是"摆设"）

| 能力 | Key | 数据结构 | TTL |
|---|---|---|---|
| 登录令牌白名单 | `ym:auth:token:{userId}` | String | 7 天 |
| 刷新令牌 | `ym:auth:refresh:{userId}` | String | 30 天 |
| 撞库保护 | `ym:auth:fail:{username}` | String 计数 | 10 分钟 |
| 热词榜 | `ym:corpus:hot` | ZSet（score=热度） | 常驻 |
| 检索结果缓存 | `ym:corpus:search:{hash}` | JSON | 5 分钟 |
| 改编结果缓存 | `ym:adapt:cache:{hash}` | JSON | 1 小时 |
| 核验结果缓存 | `ym:verify:cache:{sha256[:24]}` | JSON | 1 小时 |
| 核验结论计数 | `ym:verify:counter` | Hash（结论→次数） | 常驻 |
| 每日一词 | `ym:daily:{yyyy-MM-dd}` | JSON | 到当日 24 点 |
| 答题日榜 | `ym:quiz:rank:{yyyyMMdd}` | ZSet | 3 天 |
| 收藏镜像 | `ym:fav:set:{userId}` | Set | 常驻 |
| 接口限流 | `ym:rate:{r/w}:{ip}` | String + Lua | 60 秒 |
| 今日 UV | `ym:stats:uv:{yyyyMMdd}` | HyperLogLog | 8 天 |
| 今日 PV | `ym:stats:pv:{yyyyMMdd}` | Hash（接口→次数） | 8 天 |

限流：读 120 次/分钟、写 30 次/分钟（Lua 原子自增，`PTTL<0` 时补过期时间，避免脏 key 永久封禁）。

## 六、数据库

库 `yumai`，9 张表：`t_user` `t_corpus` `t_favorite` `t_book_fav` `t_adapt_log` `t_quiz_question` `t_quiz_record` `t_daily_word` `t_verify_log`。
`db/schema.sql` 全部 `CREATE TABLE IF NOT EXISTS`，每次启动幂等执行；播种只在表为空时进行，重启不会重复插入。

种子数据：

| 来源 | 条数 | 标记 |

> 默认只检索真实语料。「无人与我立黄昏」在语料中保留为**辟谣条目**（非《浮生六记》原文），与原报告标注一致。

## 八、已知限制（如实说明）

1. **视觉未经真实浏览器验收**：本机没有浏览器自动化（agent-browser 需另装 Chromium），
   前端只做了「接口契约 + ES Module 语法 + DOM 引用」三级代码级校验。样式与交互请在浏览器中实际过一遍。
2. **进程随终端退出**：若在受管终端（如 IDE 内置终端）里运行 `start.ps1`，子进程可能随终端关闭被回收；
   独立 PowerShell 窗口或双击 `start.bat` 正常。
3. **端口用命令行强制指定**：本机环境变量 `SERVER_PORT` 会覆盖 `application.yml`，
   因此脚本与文档一律用 `--server.port=8081` 显式覆盖（命令行参数优先级高于环境变量）。
4. **未接入真实大模型**：改编为本地规则引擎（与附录五一致），H5 版里可选的 `apiAdapt` 未移植；
   如需接入，可在 `AdaptService` 增加一个 `LlmAdaptStrategy` 分支。
5. **不修改离线存档**：`附录五-技术复原/` 下的门户与应用保持原样（该存档不随仓库分发），
   本平台改为**反向引用**它们（`/archive/**`），而不是修改它们。
6. **归档依赖外部目录**：jar 不含 13 MB 静态资产，需 `附录五-技术复原` 与本目录同级（或配置
   `yumai.archive.dir`）。缺失时只有「工具集」不可用，其余模块正常，并在页面上明确报错。
7. **归档里的 .md 走下载**：`README.md`、技术提取方案等 Markdown 在「工具集」里用「预览」（纯文本原样）
   与「下载」两个入口呈现，不做 Markdown 渲染，避免把原文排版成另一副样子。
8. **目录型项目没有 index.html**：`复原脚本`、`构建脚本` 本身不是网页，
   直接按 URL 访问会 404，因此「工具集」为它们提供「浏览目录」（`/api/archive/list`）入口，
   清单里再逐个打开或下载。
9. **核验不是全库训诂**：溯源核验的判定范围是「误传案例 43 + 真典 47 + 语料对 118」这一套索引，
   超出范围的句子一律返回「未收录」，并在页面与接口里都写明**未收录不等于伪古风**。
   真正的全库比对需要接入外部古籍语料，本版本没有做，也不假装做了。
10. **可信度是派生指标**：由误传条目加权算出，只用于提示引用风险，
    不是调研报告的统计结果（接口 `disclaimer` 字段与页面说明都写明了这一点）。
11. **名句不做校勘**：`seed/book_notes.json` 里的 77 条名句取自各书通行本并标注篇名，
    只是「可以拿去核对」的线索，不同版本字句有出入时以校勘本为准；韵书、政书、类书一类（16 部）
    只写要旨、不摘句，避免为了填满页面而编造金句。
