# 接口文档

Base URL：`http://localhost:8081/api`
统一响应：`{ "code": 0, "msg": "ok", "data": ..., "timestamp": 169... }`，`code=0` 为成功。

鉴权：登录后返回 `token`，后续请求带 `Authorization: Bearer <token>`（也支持 `X-Token`）。
标 🔒 的接口未登录返回 `code=401`；退登后令牌在 Redis 白名单中被删除，立即失效。

错误码：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数校验失败 |
| 401 | 未登录 / 令牌失效 / 口令错误 |
| 403 | 无权限 / 账号被禁用 |
| 404 | 资源不存在 |
| 409 | 冲突（如账号已注册） |
| 429 | 触发限流（读 120 次/分，写 30 次/分） |
| 500 | 服务端异常 |

## 1. 鉴权 `/auth`

### POST `/auth/register`
```json
{ "username": "demo2", "password": "secret123", "nickname": "同学" }
```
返回 `token` / `refreshToken` / `expiresIn` / `user{id,username,nickname,avatar,role}`。

### POST `/auth/login`
```json
{ "username": "demo", "password": "demo123" }
```
连续 5 次口令错误后锁定 10 分钟（Redis 计数）。

### POST `/auth/refresh`
```json
{ "refreshToken": "..." }
```
校验「类型 = refresh」且与 Redis 中记录一致，返回新 `token`。

### POST `/auth/logout` 🔒
删除 Redis 中的 access / refresh 令牌。

### GET `/auth/me` 🔒
返回 `id/username/nickname/avatar/role/createdAt/lastLoginAt/favCount/quizCount/adaptCount/bestScore`。

### PUT `/auth/profile` 🔒
```json
{ "nickname": "新昵称", "avatar": "avatar-3" }
```

## 2. 语料 `/corpus`

### GET `/corpus`
| 参数 | 默认 | 说明 |
|---|---|---|
| kw | — | 关键词，匹配现代用语 / 古风表达 / 出处 / 标签 |
| category | — | 分类，如「古风翻译体」 |
| dataSource | REAL | `REAL` 真实语料、`TEMPLATE` 模板扩充、留空为全部 |
| page / size | 1 / 12 | size 上限 60 |
| sort | default | `default` / `view` / `fav` |

返回 `{ total, page, size, pages, list[] }`，`list` 元素含
`id/code/modern/ancient/source/categories/tags/platform/popularity/era/emotion/confidence/dataSource/viewCount/favCount/favorited`。
无关键词的查询会进 Redis 缓存 5 分钟。

### GET `/corpus/{id}`
返回详情，并把浏览量 +1（MySQL）与热度 +2（Redis ZSet）。

### GET `/corpus/hot?n=8`
热度榜，读 Redis ZSet；空则回落 MySQL `view_count`。

### GET `/corpus/categories`
按「、」拆分聚合，返回 `[{name,count}]`。

## 3. 改编 `/adapt`

### POST `/adapt`
```json
{
  "text": "今天上班好困啊，不想干活只想摸鱼",
  "mode": "m2c",
  "context": "职场",
  "tone": "庄重",
  "form": "文言句式"
}
```
| 字段 | 取值 |
|---|---|
| mode | `m2c` 今→古、`c2m` 古→今 |
| context | 日常 / 职场 / 学习 / 情感 / 社交 |
| tone | 自然 / 俏皮 / 庄重 / 深情 / 豪迈 / 温婉 |
| form | m2c：原词使用 / 诗词语素拼接 / 网络改编 / 文言句式；c2m：通俗转写 / 网络改编 / 文言句式 |

返回：
```json
{
  "input": "...", "output": "夫案牍之间，今日赴职好困啊，弗欲劳作只欲偷得浮生半日闲，斯为雅正",
  "source": "《题鹤林寺僧舍》唐·李涉",
  "notes": ["命中语料库条目：「摸鱼」→「偷得浮生半日闲」", "文言词汇替换 6 处", "..."],
  "traces": [
    { "step": 1, "type": "corpus", "title": "语料对命中",
      "detail": "「摸鱼」→「偷得浮生半日闲」", "source": "《题鹤林寺僧舍》唐·李涉", "count": 1 },
    { "step": 2, "type": "lexicon", "title": "文言词表替换",
      "detail": "「不想」→「弗欲」、「只」→「只」…（共 6 处）", "count": 6 },
    { "step": 3, "type": "syntax", "title": "句式变换", "detail": "「把…当作」→「以…为」", "count": 1 },
    { "step": 4, "type": "context", "title": "语境限定", "detail": "句首加「案牍之间」", "source": "职场", "count": 1 }
  ],
  "mode": "m2c", "context": "职场", "tone": "庄重", "form": "文言句式", "hitCache": false
}
```
同参数第二次调用 `hitCache=true`（Redis 1 小时缓存）。单次输入上限 300 字；结果与调用流水同时落库。

`traces` 是**改写依据链**：每一步改了哪些字、依据哪条语料对/词表/句法规则，都能对回语料库回查。
`type` 取值 `corpus`（语料对）/`lexicon`（词表）/`syntax`（句法）/`style`（文体）/`context`（语境）/`tone`（语气）；
老版本缓存里没有该字段时返回空数组。

### GET `/adapt/options`
返回可选语境/语气/形式与 4 条示例句。

### GET `/adapt/history?n=10` 🔒
当前用户最近 10 次改编记录。

## 8. 古籍书库 `/books`

只读接口，无需登录。数据源为 `seed/knowledge.json` 的 `books` 段（60 部，经部 15 / 史部 14 / 子部 16 / 集部 15）。

### GET `/books?kw=&bu=&era=&page=1&size=24`

| 参数 | 说明 |
|---|---|
| `kw` | 匹配书名 / 著者 / 提要 / 年代 / 部类，**也匹配别名与要旨、名句**（搜「老子」能命中《道德经》） |
| `bu` | 部类精确匹配（经部 / 史部 / 子部 / 集部） |
| `era` | 成书年代精确匹配（先秦 / 汉 / 唐 / 宋 …） |
| `page`/`size` | 分页，`size` 上限 60 |

```json
{ "list": [{ "name":"周易","bu":"经部","era":"先秦","author":"相传伏羲、文王、孔子",
             "intro":"群经之首…","seed":695979,"color1":"#2f6b57","color2":"#6aa88c",
             "quoteCount":3 }],
  "total": 60, "page": 1, "size": 24, "pages": 3,
  "bus": [{ "name":"经部","count":15 }], "eras": [{ "name":"先秦","count":11 }], "poolSize": 60 }
```

`seed/color1/color2` 为**确定性封面参数**：`seed = 逐字符 h*31+code 取无符号 32 位`，与 H5 版
`hashCode()` 完全一致，因此同一本书在两端是同一张封面（渐变底色由部类决定）。

### GET `/books/{name}`

书名需 URL 编码（如 `/books/%E8%AE%BA%E8%AF%AD`）。返回书目元数据 + 增强层 + 五类关联：

| 字段 | 说明 |
|---|---|
| `note` | **要旨**：这本书在文言考据／改写里有什么用（60 部全有） |
| `quotes` | **名句摘录** `[{text, from}]`，句后带篇名便于核对；46 部共 77 条，工具型典籍为空数组 |
| `alias` | 通行别名（`道德经` → `老子`、`周易` → `易经`），参与出处匹配与检索 |
| `buIntro` | 部类导读（经／史／子／集四段之一） |
| `relatedPairs` | **直接引用**：出处（`source`）中含书名或别名的语料对 |
| `buPairs` | **同部类参考语料**（最多 6 条）：仅在 `relatedPairs` 为空时给出，**不是本书引文** |
| `authorPairs` | **同作者作品**：作者相同、被语料引用的条目，是否收入本集未逐篇核对 |
| `relatedCalendar` | 相关日历词条（命中书名/别名，或命中本书名句的篇名，如《水调歌头》→ 东坡乐府） |
| `sameBu` | 同部其他典籍（最多 8 部，带 `quoteCount`） |
| `relatedPairCount` / `relatedCalendarCount` / `quoteCount` | 三类计数 |
| `honest` | 数据诚实声明（不提供全文；同部类参考不是本书引文） |

> 设计动机：60 部书里原本只有 10 部能在报告语料中找到直接引用，其余 50 部点开是空页。
> 现在每部书至少有「要旨 + 名句／同部类参考／同部荐读」之一，**60 / 60 无空页**；
> 同时把「直接引用」「同部类参考」「同作者作品」分开标注，不把参考当引文。

不存在时返回 `code=404`。

### GET `/books/random`

随机取一部，供「随便翻一本」。

## 9. 科普日历 `/calendar`

### GET `/calendar`

```json
{ "date":"2026-10-17", "poolSize":16, "todayIndex":8,
  "today": { "word":"重要的事说三遍", "…":"…" },
  "list": [{ "index":1,"word":"快哉快哉","category":"古风诗词语素拼接","modern":"太爽了 / 好耶",
             "source":"化用苏轼…","grammar":"…","usage":"…","misuse":"…",
             "examples":["…"],"corpusId":12,"today":false,"nextDate":"2026-10-26" }],
  "rule":"按「日序 % 词条数」确定性排期…" }
```

排期规则与 `/daily` 一致（`epochDay % poolSize`），因此 `today.word` 恒等于 `/daily` 的 `word`——
自检脚本对此做了断言。`nextDate` 为该词条下一次出现的日期（当天即为今天自身）。

## 10. 归档 `/archive`

把 `附录五-技术复原` 的 25 项交付物（6 组）挂到统一入口。

### GET `/api/archive/catalog?refresh=false`

```json
{ "available": true,
  "root": "D:\\…\\附录五-技术复原",
  "hint": "",
  "totalItems": 29, "missingItems": 0, "indexedFiles": 209, "indexedBytes": 13201661,
  "groups": [{ "name":"核心应用", "note":"…",
               "items":[{ "id":"WB","emoji":"🧭","name":"统一工作台","desc":"…",
                          "meta":["19 项 · 60 KB"],"tags":["整合入口"],
                          "path":"统一工作台.html",
                          "url":"/archive/%E7%BB%9F%E4%B8%80%E5%B7%A5%E4%BD%9C%E5%8F%B0.html",
                          "kind":"html","exists":true,"bytes":61339,"files":1 }] }] }
```

- `path` 为相对归档根目录的原始路径，`url` 为已编码的访问地址；
- `kind` 取值：`html` `md` `json` `txt` `docx` `dir` `image`；
- `exists/bytes/files` 每次调用前复核磁盘（`?refresh=true` 强制重新探测根目录）；
- 根目录探测失败时 `available=false`，`hint` 给出修复方式。

### GET `/api/archive/stat`

同上但只返回计数与路径，用于首页/健康页轻量展示。

### GET `/api/archive/list?path=复原脚本`

浏览归档内子目录（目录型项目没有 `index.html`，直接访问 URL 会 404）。

```json
{ "path":"复原脚本", "parent":"", "dirCount":2, "fileCount":14,
  "dirs":[{ "name":"构建脚本","path":"复原脚本/构建脚本","url":"/archive/…","files":46 }],
  "files":[{ "name":"check_links.py","path":"复原脚本/check_links.py","url":"/archive/…",
             "bytes":2173,"kind":"file" }] }
```

`path` 为空时列归档根目录；越出根的路径（`../`）返回 `code=404`。

### GET `/archive/**`

静态托管，直接输出原文件（不注入任何本站样式/脚本）。
目录穿越（`..`）被 `PathResourceResolver` 拦截返回 404；`.md` 以 `application/octet-stream` 下发，
前端用「预览」（`fetch` 取文本渲染 `<pre>`）与「下载」两个入口处理。

## 11. 溯源核验 `/verify`

报告的核心命题是「反伪古风」。这一组接口把附录五 P1「古风用语规范助手」的判定数据搬到服务端：
误传案例库 43 条 + 真典库 47 条，运行时建 555 条索引，供全平台复用。

### 判定口径（与 P1 完全一致）

| 结论 | 触发条件 | order |
|---|---|---|
| 伪古风 | 命中误传库且等级为「伪古风」（查无此句、今人拟古） | 3 |
| 出处讹变 | 命中误传库且等级为「出处讹变」（句子存在但出处被张冠李戴） | 3 |
| 出处存疑 | 命中误传库且等级为「出处存疑」（有相似古句，归属不确定） | 3 |
| 真伪混杂 | 同一批文案里既有可溯源真句，又有误传条目 | 2 |
| 有据可考 | 只命中真典库或语料对 | 1 |
| 未收录 | 一条都没命中 | 0 |

**「未收录」不等于伪古风**——接口在 `summary` 与 `disclaimer` 两处都写明了这一点。

### POST `/verify`

```json
{ "text": "人生若只如初见\n无人与我立黄昏，无人问我粥可温" }
```

```json
{ "mode": "batch", "inputLength": 29,
  "segments": [
    { "index": 1, "text": "人生若只如初见",
      "verdict": { "name": "有据可考", "order": 1, "summary": "…" },
      "counts": { "total": 1, "traceable": 1, "suspect": 0, "modern": 0,
                  "fake": 0, "corrupt": 0, "doubtful": 0 },
      "hits": [{ "label": "人生若只如初见，何事秋风悲画扇", "level": "有据可考",
                 "kind": "verified", "source": "清·纳兰性德《木兰花·拟古决绝词柬友》",
                 "check": null, "pos": 0 }] }
  ],
  "overall": { "name": "真伪混杂", "order": 2, "credibility": 65, "credLabel": "需再核一次",
               "counts": { "total": 2, "traceable": 1, "suspect": 1, "modern": 0,
                           "fake": 1, "corrupt": 0, "doubtful": 0 },
               "summary": "…", "advice": ["不要标注为沈复原文；…"] },
  "indexSize": 555, "casesTotal": 43, "verifiedTotal": 47,
  "cacheHit": false, "disclaimer": "「可信度」是本平台依据误传案例库派生的辅助指标…" }
```

- 换行即分段，最多 20 段；单次 ≤ 2000 字，超出返回 `code=400`；
- 结果按 `sha256(text)[:24]` 缓存 1 小时（`ym:verify:cache:*`），重复提交 `cacheHit=true`；
- `ym:verify:counter` 按结论累计计数，`/verify/meta` 可读；
- 登录用户的每次核验写入 `t_verify_log`，未登录只算不存。

**可信度**是派生指标（不是报告统计值）：
`100 − 伪古风×35 − 出处讹变×22 − 出处存疑×12 − 现代网语×3`；
无一条可溯源时封顶 40；一条都没命中时不出分（字段缺省，前端显示「—」）。
分档：≥85 可放心引用 / 60–84 需再核一次 / 40–59 风险较高 / <40 高风险·建议改写。

### GET `/verify/cases?kw=&level=&page=1&size=20`

误传案例库，按等级筛选、分页。`kw` 命中句子/常见误标/实际情况/建议/核验方式任一字段。
带 `kw` 时额外返回 `relatedVerifiedTotal` 与 `relatedVerified`（真典库命中，最多 5 条），
避免把「纳兰性德」这类真句误判成伪古风。

### GET `/verify/verified?kw=`

真典库条目（`text` + `source`），用于「这句话到底出自哪」。

### GET `/verify/meta`

`casesTotal` / `verifiedTotal` / `indexSize` / `levels`（各等级条数）/ `verdictCounter`（Redis 计数）。

### GET `/verify/history?n=10` 🔒

当前用户的核验流水：`input` / `verdict` / `credibility` / `hitCount` / `suspectCount` / `time`。
